What sparse replay can and cannot prove

Historical fieldCRS handlingCoverage
Raw path and queryProcessURI populates URI and GET argument variablesEvaluated
Method and protocolRequest transaction metadataEvaluated
User-Agent, Referer, XFFAdded only when the log contains themConditional
Request body and cookiesCannot be reconstructed when absentMissing
Response headers and bodyResponse phases are not executed by this profileNot evaluated
CRS protocol group 920Removed to prevent false findings caused by unrecorded headersExcluded
A no-match result is not a benign verdict. Every result carries observed fields, missing fields, and evaluated phases so the report generator can state the limit plainly.

Repository changes

crs-replay/main.go

Long-running JSONL replay command. Loads Coraza and CRS once, reconstructs transactions, and returns matched rules with provenance.

crs-replay/go.mod

Pins Coraza 3.7.0 and the embedded CRS 4.25.0 package for Go 1.25.

stage2-path2-triage-pipeline-v2.py

Runs offline replay once per HTTP batch and maps attack-tagged CRS matches into detector evidence.

stage3-anchor-hunter-pivot-v2.py

Recognizes offline CRS findings as signature-backed anchors.

detection/http-signatures.json

Versioned application-specific rules. These remain clearly separate from CRS.

detection/threat-intel.json

External IOC snapshot contract with feed name, version, confidence, and severity.

offline-crs-research.md

Primary-source research covering the Coraza lifecycle, replayable fields, blind spots, and CLI choice.
